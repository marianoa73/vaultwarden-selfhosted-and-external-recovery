# Hosting, backup destinations and encryption options

[Versión en español](options.md)

The reference design uses a small home server, a remote VPS and open-source tools, but none of that is mandatory. This page lists the alternatives for **where things run**, **where the encrypted copies go** and **how to protect the keys**, and the one rule that never changes: **everything is encrypted before it leaves the machine, and the passphrase is kept apart from the copies.**

## Where the server and the standby can run

| Option | Good for | Watch out for |
|---|---|---|
| Small physical machine at home (mini PC, single-board computer) | the primary: low power, always on, under your control | needs a UPS and a second location for the copies |
| **Virtual machine on your own hardware** (Proxmox, KVM/libvirt, Hyper-V, VirtualBox, a NAS hypervisor) | the primary or the standby; easy snapshots and fast rebuild | a VM on the same host as the primary does not survive the loss of that host: keep the standby on a different machine |
| **VPS** (any small cloud server) | the remote receiver and a switched-off standby, off your premises | it is somebody else's hardware: only encrypted archives live there, no passphrase, no route to your home network |
| Container only, on any Linux or on Windows through WSL2 | a first try or a laptop setup | the host must be on at backup time; a desktop or always-on machine is better |
| Second physical machine in another place (family, office) | a standby you control | needs the same hardening as the primary |

The primary and the standby must not share the same failure: different machine, different place, ideally different network.

## Where the encrypted copies can go

| Destination | How | Notes |
|---|---|---|
| Remote host over SSH (default) | `vw-send.sh` with a restricted key and a forced command | the receiver can store but never open the archives |
| **Cloud drive** (Google Drive, OneDrive, Dropbox) | `vw-copy.sh` through `rclone`, `VW_RCLONE_REMOTE` | convenient and cheap; the archive is already encrypted, so the provider cannot read it |
| Object storage (S3-compatible, Backblaze B2, others) | the same, through `rclone` | enable versioning or object lock, so a deleted or overwritten copy can be recovered |
| External disk, USB drive or NAS share | `vw-copy.sh`, `VW_COPY_DIR` | keep one disk offline and away from home; disconnect it after the copy |
| SFTP or WebDAV server | the same, through `rclone` | any server you trust to store files, not to read them |

Aim for the 3-2-1 rule: **three copies, on two kinds of media, one of them off-site.** Use a dedicated account or folder with the smallest permissions, with two-step sign-in, and never reuse the vault's own account.

## Encryption at the highest level

- **Encrypt before sending.** The archive is a GnuPG file with AES-256 and the strongest key-derivation setting (`--s2k-mode 3`, maximum iteration count). The cloud provider's own encryption is an extra layer, never the only one.
- **Verify by decrypting.** Every new archive is opened and its database checked before it replaces anything. An archive you have never opened is not a backup.
- **A long random passphrase**, at least 128 bits (48 random bytes is plenty), generated by the script and never chosen by hand. It is a different secret from the master password.
- **Public-key variant (stronger for the server).** If the machine that makes the backups only holds a public key, a compromised server cannot read old archives, and the private key stays offline. It needs a small change in the scripts (encrypt in `vw-backup.sh`, decrypt in `vw-restore.sh`):

```bash
# on the primary: only the PUBLIC key is imported
gpg --batch --yes --encrypt --recipient recovery-key --cipher-algo AES256 -o vault.tar.gpg vault.tar
# on the recovery machine: the PRIVATE key, kept offline, opens it
gpg --decrypt vault.tar.gpg > vault.tar
```

- **Never upload anything readable.** `vw-copy.sh` refuses a file that is not GnuPG-encrypted.
- Keep the cloud tool's own configuration (the access token) with mode 600 and a small scope: it can write backups, nothing else.

## Where the passphrase lives

The copies are only as safe as the passphrase, so it lives **apart from them**:

- On **paper, in two separate places** (home safe, a relative's house, a bank box). Nothing else is the primary copy.
- **Never in the same cloud account, disk or server** as the archives, and **never inside the vault itself**: if you lose the vault you also lose the key to its backups.
- Optionally split it in parts among people you trust (for example 2 of 3), so no single person can open the backups and the loss of one part is survivable.
- A hardware token or an offline password manager can be a second copy, never the only one.
- Write down **what it is for and where the archives are**, not the passphrase and not the location in a shared document.
- If the passphrase may have been seen, generate a new one, make a new backup and retire the old copies.

## Disaster recovery levels

| Level | What you keep | Recovery time | Recovery point |
|---|---|---|---|
| Archives only (cold) | encrypted copies in two places | hours: install the server on any machine and restore | the last night |
| Standby VM on another machine | the same image, switched off | minutes to an hour: start and restore | the last night |
| Standby on a VPS | the same image, switched off | minutes to an hour, from anywhere | the last night |
| Warm standby (receives the copy and is checked daily) | the same image, restored on a schedule | minutes | the last night |

Pick the lowest level that your family can live with, and rehearse it. The emergency contact ([emergency-access.en.md](emergency-access.en.md)) is the last safety net, not the plan.

## Configure a second destination

Add one or both lines to the private environment file, then run a backup by hand:

```bash
# /etc/vw-recovery.env  (mode 600)
VW_COPY_DIR=/path/to/mounted/disk          # external disk, NAS share or second machine
VW_RCLONE_REMOTE=mydrive:vault-backups     # an rclone remote and folder you created with: rclone config
```

```bash
sudo systemctl start vw-backup.service && journalctl -u vw-backup.service -n 20
rclone lsf mydrive:vault-backups            # you should see the .tar.gpg and its .sha256
```

Then restore from **that** copy on a spare machine at least once, as described in [recovery](recovery.en.md).

## Checklist

1. Server and standby on different machines, ideally in different places.
2. At least three copies, two kinds of media, one off-site.
3. Every copy encrypted before it leaves the machine, verified by decrypting.
4. Passphrase long, random and different from the master password.
5. Passphrase on paper in two places, never next to the archives and never in the vault.
6. Dedicated storage account, small scope, two-step sign-in.
7. Versioning or object lock where the provider offers it.
8. A restore rehearsal from each destination at least every quarter.
9. The age of the last backup in a daily status message.
